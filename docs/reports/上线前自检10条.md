# 上线前自检 10 条（组员6 · 验收裁判官）

> 用法：发布前逐条核对，打勾 ✅ / 打叉 ❌，任何一条 ❌ 不得上线。
> 项目：旅游规划智能体系统 · 对应课程设计第三/四阶段。

## 一、功能闭环

- [ ] **1. 登录流程贯通**：手机号+密码登录 → 返回 token → 前端存 token → 后续请求自动带 `Authorization: Bearer <token>`。
- [ ] **2. 验证码可用**：图形验证码能正常切换、短信验证码 60 秒倒计时防重复发送。
- [ ] **3. 找回密码链路**：忘记密码 → 验证码校验 → 重置成功 → 能用新密码登录。
- [ ] **4. Token 过期自动刷新**：401 时前端用 refresh_token 静默换新，用户无感知；refresh 也失效时跳回登录页。

## 二、权限控制

- [ ] **5. 菜单级权限**：用户登录后按角色只看到自己有权的菜单项（无权限菜单不渲染）。
- [ ] **6. 按钮级权限**：`<AuthPermission>` 组件对"导出""下架"等按钮按权限置灰/隐藏。
- [ ] **7. 路由守卫**：直接在地址栏输无权限 URL，被拦截并提示 403。

## 三、稳定性

- [ ] **8. 后端健康检查**：`GET /v1/health` 无需登录返回 200，标准响应包络中 `data.status = "ok"`。
- [ ] **9. Mock 切真地址无残留**：前端 BaseURL 已从 Apifox Mock 切到真实后端，没有硬编码 mock 域名。
- [ ] **10. 关键接口冒烟通过**：登录 / 当前用户 / 权限列表 / 角色列表 / 用户列表，5 个核心接口联调均 200。
