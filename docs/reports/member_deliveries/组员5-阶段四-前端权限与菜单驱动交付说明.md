## 三、拉取前序代码后修正的关键口径

1. **游客会拿到「后台菜单」**：`08_rbac_complete.sql` 给 TOURIST 的 6 个 C 端按钮，
   会被 `rbacRouter.visiblePermissionIds()` 沿 `parent_id` 补出 `/chat`、`/orders`、
   `/itineraries` 等祖先菜单。因此**不能按菜单路径判断管理中台入口**——拉取前那版会误把游客当管理员，
   本版改为只看管理类按钮码（`system:*`、`route:line:*`、`order:manage:*`、
   `itinerary:plan:query|update|delete|export`）与 `system` 模块菜单，并加了回归用例。
2. **后端 `menus` 是后台菜单树，不是 C 端 Tab**：只有显式前台 Tab 菜单才严格按菜单渲染；
   当前按权限视角决定 Tab 集合——游客 2 个（`plan` + `profile`），超管/社管全部 5 个。
3. **Tab 可见性 ≠ 页面可达性**：游客点「创建计划」要能进智能体/行程下钻页，
   所以可达屏白名单 = 可见 Tab + 下钻页 + 有条件加入的 `admin`，越权进 admin 仍被挡。
4. **权限刷新即生效**：挂载 / `focus` / `visibilitychange` 重拉 `menus/buttons` 写回会话，
   `AdminScreen` 的 `<AuthPermission code="route:line:add">` 随之重渲染——
   对应验收「取消 AGENCY_ADMIN 的 `route:line:add` 后刷新即看不到『上架新路线』」。
5. **Idempotency-Key 每次换**：`RoleManage` 在点击保存瞬间调 `newIdempotencyKey()`，
   随提交体交给父组件，不存 state、不复用；`lib/http.ts` 拦截器显式传值时以传入为准。
