# 前端提速前后对照

## 首屏指标

以下是同一浏览器、本地生产预览、每个尺寸 3 次重载的中位数。FCP/LCP/CLS 来自浏览器 Performance API；TBT 栏是 long-task 估算，并非 Lighthouse TBT。Speed Index 尚未取得，不能把这些数据当作 Lighthouse 报告。

| 设备 | 指标 | 优化前 | 优化后 | 变化 |
|---|---|---:|---:|---:|
| Desktop | FCP | 88 ms | 100 ms | +12 ms |
| Desktop | LCP | 88 ms | 116 ms | +28 ms |
| Desktop | TBT（long-task 估算） | 0 ms | 0 ms | 无变化 |
| Desktop | CLS | 0 | 0 | 无变化 |
| Mobile | FCP | 88 ms | 76 ms | -12 ms |
| Mobile | LCP | 88 ms | 92 ms | +4 ms |
| Mobile | TBT（long-task 估算） | 0 ms | 0 ms | 无变化 |
| Mobile | CLS | 0 | 0 | 无变化 |
| 两种设备 | Speed Index | 未测 | 未测 | Lighthouse CLI 安装受阻 |

本机样本波动较大，桌面 LCP 在这组测试中没有改善；不能仅凭 FCP 声称整体变快。下一步应在可用的 Lighthouse 环境重复多轮测量，再评估首屏懒加载带来的网络请求时序。

## 首屏 JavaScript

| 构建 | 首屏 JS 原始字节 | 浏览器记录的首屏 JS 传输字节 | 首屏模块 |
|---|---:|---:|---|
| 优化前 | 266,429 B | 88,609 B | 单一入口包，包含所有页面 |
| 优化后 | 246,252 B | 84,999 B | 入口、React/HTTP vendor、计划页 chunk |
| 变化 | -20,177 B（-7.6%） | -3,610 B（-4.1%） | 其余页面按需下载 |

优化后完整 JS 产物为 268,907 B；总量略高于原单包，但未访问页面的 chunk 不在计划页首屏请求中。首屏传输体积才是本次代码拆分的直接收益指标。

## 图片与缓存

- 优化前没有本地景点图片；优化后 9 个 WebP 变体（3 张占位图 × 480/960/1440）合计 50,558 B。
- 首次打开探索页只请求 3 张 480w 变体，传输共 6,946 B；它们使用 `loading="lazy"`、`srcset`、`width` / `height`。
- 本机 Redis 未启动，`routes:hot` / `spots:hot` 的 warmup 被跳过；缓存代码已接线，但命中率、预热耗时和 Redis 命中日志仍需在 Redis 可用环境验收。
- 当前环境没有 Nginx，gzip/Brotli、长缓存头、HTML no-cache 和 WS Upgrade 配置未能以 `nginx -t` 或浏览器响应头验证。
