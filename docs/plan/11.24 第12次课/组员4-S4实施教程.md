# 组员4 · S4 实施教程（实时域与定时器）

> 配套文档：`docs/plan/实时边界说明.md`（契约）、`交接-S4-实时域与定时器.md`（交付清单与风险）。
> 目标：30 分钟内把 S4 的四件事在自己机器上跑通并留下可演示的证据。

## 0. 前置检查（5 分钟）

```powershell
# Node 在 :3001，Java 在 :8080，MySQL/Redis 已起
curl http://localhost:3001/healthz          # 期望 200
curl http://localhost:8080/api/auth/me -b cookies.txt   # 先登录再验
```

`.env`（Node）与 `application.yml`（Java）两边必须一致：

| 变量 | Node `.env` | Java `application.yml` |
|---|---|---|
| 内部密钥 | `INTERNAL_API_SECRET=<≥32 字符>` | `app.internal.secret: ${INTERNAL_API_SECRET:}` |
| 白名单 | `INTERNAL_ALLOWED_IPS=127.0.0.1,::1` | 无（由 Node 校验 Java 的出口 IP） |

**密钥不一致的典型症状**：定时任务四条全 `ok=false`、大屏提示"预聚合读取失败（401）"。
**IP 不在白名单的症状**：HTTP 404 且响应体为空（Node 故意不回包络）。

## 1. 编译与单测（10 分钟，首次会下载依赖）

```powershell
cd java-web
.\mvnw.cmd '-Dskip.frontend=true' test
```

期望：`AuthFlowTest`（4）+ `NodeApiClientTest`（5）+ `RequestSignerTest`（2）
+ `WsTicketServiceTest`（4）+ `InternalSignerTest`（3）全绿。

> 前端不建议每次都跑 `npm ci`；只在改了 `agency-web` 的 TS 时执行
> `npm --prefix agency-web run build`（首次需要 `npm ci`，网络慢可等评委电脑）。

## 2. 起服务并确认定时器活着（5 分钟）

```powershell
.\mvnw.cmd spring-boot:run '-Dskip.frontend=true'
```

启动日志里能看到 `Scheduler class: 'org.quartz.core.QuartzScheduler'` 与四个 Job 的注册；
每 10 秒应出现一条：

```
定时任务 成功 task=expire-orders 耗时=37ms 结果={"task":"expire-orders","processed":0}
```

台账接口（浏览器登录后直接开）：

```
GET http://localhost:8080/api/internal/timers
→ { timers_enabled: true, timers: { "expire-orders": { task, started_at, duration_ms, ok, message }, … } }
```

**判据演练 A（单任务失败不影响其他三个）**：临时把 `app.internal.fail-task` 设成
`refresh-stock`，重启 → 该任务每轮 `ok=false`，另外三条约 10 秒后仍是 `ok=true`。验完改回空串。

## 3. 票根：一次性 + 过期（5 分钟）

1. 浏览器登录 `http://localhost:8080`，F12 → Console：

   ```js
   const r = await fetch('/api/realtime/ticket', {
     method: 'POST',
     headers: { 'X-XSRF-TOKEN': document.cookie.match(/XSRF-TOKEN=([^;]+)/)[1], 'Content-Type': 'application/json' },
     body: '{}',
   }).then((x) => x.json())
   r.data.ticket   // 43 字符
   ```

2. 用同一串 ticket 连两次 SSE：

   ```js
   const t = r.data.ticket
   await fetch(`/api/stats/live?ticket=${encodeURIComponent(t)}`).then((x) => x.status)  // 200
   await fetch(`/api/stats/live?ticket=${encodeURIComponent(t)}`).then((x) => x.status)  // 401
   ```

3. 换一张新票，等 31 秒再连 → 401。

4. 在 Network 面板检查 WS/SSE 的 URL 只有 `ticket=`；Response 里 grep 不到 `token`。

## 4. 客服台（5 分钟）

打开 `/agency/livedesk`：
- 连接指示灯变绿（WS 经 `/api/im/ws?ticket=…`）；
- 游客端发一条消息 → 客服台 1 秒内出现；
- 客服台回复 → 游客端收到（帧经 BFF 桥接，浏览器全程没有 token）。

## 5. 大屏与预聚合判据（10 分钟）

打开 `/agency/bigscreen`：

1. 四个数字有值、ECharts 曲线可读、实时域三个数字在跳；
2. 点「立即预聚合」→ 数字与"生成于 N 秒前"同时刷新；
3. **判据演练 B（停预聚合数字停更）**：`app.internal.timers-enabled: false` 重启（或把
   `fail-task` 设成 `dashboard-preagg`）→ 观察 5~6 分钟后：
   - "生成于"持续变大，超过 6 分钟出现红色提示"预聚合已 N 分钟未更新"；
   - 曲线走平，四个数字停在最后一轮；
   - 改回 `true` 重启 → 约 5 分钟后恢复更新（或再点「立即预聚合」）。

## 6. 常见故障对照

| 现象 | 优先看 |
|---|---|
| 四条任务全 `ok=false`，日志 `401` | 两边 `INTERNAL_API_SECRET` 是否逐字一致、是否 ≥32 字符 |
| 四条任务全 `ok=false`，日志 `404`/空响应体 | Java 出口 IP 是否在 `INTERNAL_ALLOWED_IPS` 内 |
| `dashboard-metrics` 恒为 0，页面提示"尚未生成" | `dashboard-preagg` 有没有成功跑过一轮（先手动 `POST /api/internal/timers/dashboard-preagg`） |
| 大屏一直"连接中" | SSE 换票失败（看 401）：会话过期 / CSRF 头缺失 |
| WS 建连即断，浏览器控制台 1006 | 票根过期（>30s）或握手 401：检查是不是复用了旧 ticket |
| `AuthFlowTest` 报 `ServerContainer` 缺失 | 已修（问题单 #3，`@MockBean`）；确认用的是本仓库版本 |
