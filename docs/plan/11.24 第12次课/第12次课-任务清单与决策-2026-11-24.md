## 2. 已定决策（不要再翻案，翻案要改文档）

### D1 · T1 走规范 v3，不走切换点 B 的原意

- 规范 v3 已把 **SPA 源码收进 `java-web/agency-web`**，`frontend-maven-plugin` 在 `mvn package` 里构建，产物进 `target/classes/static`，由 **Spring Boot 同源托管 :8080**，后端+前端**打成一个 jar**。
- **没有 Nginx 托管、没有 CORS 配置**；Nginx 只在生产做外层 TLS 反代（可选）。
- 同源后 **CSRF 启用**（`CookieCsrfTokenRepository` + `X-XSRF-TOKEN`），不再用"关闭 + 三条补偿"。
- 浏览器只持两个 Cookie：`JSESSIONID`（HttpOnly）与 `XSRF-TOKEN`（仅供 CSRF）。**token 与 HMAC 密钥止于 Java 服务端**。
- BFF 三职责：Session 认证、HMAC 签名、**页面级聚合（一页一请求）**。
- 收益定位：`/v1/admin/*` 只对 Java 出口 IP 开放，浏览器永远碰不到；C 端 App 仍直连 Node（Node 本来就是公网面）。
  > 答辩话术：「同一个 Node 服务，C 端业务面对公网，管理面只对内网 BFF 开放。」

### D2 · T2 只迁秒杀，IM 的 `im:notify` 保持 Redis Stream

三条理由（写进 `docs/plan/im-群聊扩散选型.md` 与交接文档）：

1. 消费逻辑与 Redis 强耦合（查 `im:online:*`、`INCR im:offline:*`），迁 Kafka 后仍要回 Redis，多一跳网络、收益为零；
2. 聊天通知是低频轻量消息，无削峰、无重放需求，Kafka 的强项用不上；
3. 现有 `XREADGROUP` + PEL 重认领已做对，Redis 挂时整条链路安静降级；迁 Kafka 后会出现"Kafka 在转、Redis 挂了"的部分故障。

**分界线**：迁移与否看的不是"技术栈统一"，而是**消费逻辑的依赖在哪里**——秒杀/埋点的下游是 MySQL 和 Flink，天生适合 Kafka；IM 的下游就是 Redis 本身。

答辩统一口径：「秒杀和埋点用 Kafka，因为要削峰、要接 Flink、要持久重放；IM 离线通知用 Redis Stream，因为强依赖 Redis 在线状态、量级轻、要安静降级。」

### D3 · T2 的消费语义映射（代码和文档都按这个写）

| Redis Stream 原来 | Kafka 之后 |
|---|---|
| 消费组 `seckill:group` | consumer group `seckill-worker` |
| 处理完成 `XACK` | 处理成功后 `commitSync`（**手动提交**，不许自动提交） |
| PEL 崩溃重认领 | rebalance 后未提交 offset 自然重投 |
| `seckill:stream:dlq` | `seckill.dlt` |
| — | 新增重试 topic `seckill.retry`，最多 3 次，退避 1s/5s/30s |
| `XLEN` 观测堆积 | `kafka-consumer-groups --describe` 的 **LAG** |

**一致性红线**：Lua 预扣成功但消息发送失败 → 必须回补 Redis 库存；**Kafka 不可达时接口直接 503 fail-fast**，绝不允许"扣了库存、消息没发出去"。对外接口 `POST /v1/seckill/:routeId`、`GET /v1/seckill/result/:reqId` 语义不变。

### D4 · T4 定时器落点定稿（Java 触发、Node 落库）

- 一律 **Java `@Scheduled`（或 Quartz）→ 调 Node `/internal/timers/*`**，Java 绝不直接写 MySQL（守住"Node 是 34 张表唯一写入方"）。
- 现有 4 处裸 `setInterval`（`api/router.ts:52` 过期订单扫描、`stock.ts:68` 库存 tick、`statsRouter.ts:292` SSE、`im/presence.ts:176` 在线状态）是本任务的**改造对象**，不是新加功能。
- 四个场景：`expire-orders`（超时订单取消）、`refresh-stock`（库存预热，低峰跑）、`seckill-toggle`（秒杀活动上下架）、`dashboard-preagg`（大屏预聚合）。
- 工程化要求：任务隔离、异常捕获 + 告警、执行日志（可在大屏/审计页看到）、幂等（条件更新或覆盖写）。

### D5 · T3 只交付 Kotlin 原生

- `frontend/android`（Capacitor 版）降级为**原型参照、非交付物**，README 标注，不删不改。
- 开工前先按规范 §14.3 交 P0 裁剪表。
- 验收硬项：`frontend/src/lib/http.ts` 的四个拦截逻辑（签名 / 幂等 / 401 刷新 / 包络剥壳）移植为 OkHttp `Interceptor` + `Authenticator`，顺序 `Auth → Signing → Idempotency`，**401 刷新必须走 `Authenticator`**（走拦截器会递归）。

### D6 · T5 链路与事件契约

链路：`埋点 → Kafka(rec.events) → Flink 窗口聚合 → Redis 画像 → /v1/rec/home → 端上展示`。

事件契约（`docs/plan/埋点事件契约.md`）：

```
POST /v1/events（单条或批量 ≤50）
{ userId, itemType, itemId, eventType, ts, sessionId, extra? }
eventType: impression | click | dwell | like | favorite | share | order
约束：异步发送、失败只记本地不阻塞主链路；Kafka key = userId（同用户有序）
```

- SPA 不直连 Node，走 Java 的 `POST /api/events` 透传。
- 在线打分（精排）可不做；**埋点采集 + Flink 算兴趣必须做**；端上"为你推荐"是加分项。
- Flink 最小可跑方案：JM+TM 单节点、不开 checkpoint；埋点量小时用造数脚本回放。
- 冷启动兜底：无画像给热门，别让页面空着。

### D7 · T7 日志是"双端 + 三类"

| 类别 | 数据源 | 表 |
|---|---|---|
| 系统日志 | Java `Logback` JSON 文件、Node `pino` JSON 文件 | 不落库，页面读文件尾部（分页 + 级别过滤） |
| 操作日志 | Node 侧埋点（点赞/收藏/下单/管理操作） | `sys_operation_log` |
| 登录日志 | Node `/auth/*` 埋点 | `sys_login_log` |
| 权限变更审计 | 已有 | `sys_audit_log`（扩展 `client_ip`、`ua`、`result`） |

- 三张业务表**都由 Node 写**（唯一写入方），写失败不得影响主链路。
- 强制脱敏：手机号中间四位、密码、token、`Authorization`、`X-Signature` 一律禁止落盘。

### D8 · T11 内部接口是"后门"，三条必须全做

1. 外层 Nginx/防火墙**不为 `/internal/*` 配任何 location**，只放行 Java 出口 IP；Node 侧 `/internal/*` 绑内网、公网访问返回 404；
2. 用**独立内部密钥**做 HMAC，**不复用用户 token**；
3. 请求带 `X-Timestamp` + `X-Nonce`，服务端做 5 分钟时间窗 + nonce 去重。

> 这条同时是 T6 的扫描项：在扫描报告里写"验证 `/internal/*` 公网不可达"，答辩时是完整的攻防闭环。

### D9 · T9 大屏只读预聚合结果

- 定时任务把统计算好写 Redis/表，前端**轮询结果**，**禁止每次轮询触发全表统计**（老师讲"统计任务放低峰"就是为这个）。
- 大屏四个数字必须"真的在动"，且关掉定时任务后数字停更——这才能证明不是前端假动。

### D10 · T8 文档同步规则

- **代码合并前文档先改**：接口字段变更 → 先改 `docs/specs/API_V1.md`；能力/边界变更 → 改 `docs/三端实施方案.md` 对应章节；表结构变更 → 改 `docs/specs/数据库设计`。
- 规范文档路径已变：**`docs/三端实施方案.md`**（不在 `docs/specs/` 下，别再找错）。
- `docs/plan/` 下的过程文档（交接、方案、教程）由各人自己维护，不作为验收件。
