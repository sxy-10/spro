# 实时边界说明（S4 交接包 · 浏览器只拿 ticket、不拿 token）

> 适用：客服台 `/agency/livedesk`、实时大屏 `/agency/bigscreen`。
> 面向下一阶段（S5 C 端 Kotlin）与验收：**这条边界不能被绕开，绕开就等于把 Node 的 token 交给前端。**

## 1. 一次连接的完整路径

```text
浏览器                     Java BFF（:8080）                    Node（:3001）
  │  POST /api/realtime/ticket   │                                  │
  │ ───────────────────────────► │  从 HttpSession 取 Node token     │
  │ ◄─────────────────────────── │  签发 30s 一次性票根（内存）       │
  │  {ticket, expires_in:30}     │                                  │
  │                              │                                  │
  │  WS  /api/im/ws?ticket=xxx   │  握手：consume(ticket) → token    │
  │ ───────────────────────────► │ ──── ws /v1/im/ws?token=… ──────► │
  │                              │ ◄──── 帧双向桥接（不含 auth 帧）── │
  │                              │                                  │
  │  SSE /api/stats/live?ticket= │  同上：取票 → 用 token 打开上游    │
  │ ───────────────────────────► │ ──── GET /v1/stats/live ────────► │
```

三条红线：

1. 浏览器只持有 `JSESSIONID`、`XSRF-TOKEN` 和**一次性票根**；响应体里永远没有 `token`；
2. 票根 **30 秒有效、用后作废**（`WsTicketService` 用 `ConcurrentHashMap.remove` 做原子消费，
   第二次用同一票根必然 401）；
3. Java 连 Node 仍用 Bearer（`NodeStreamClient` / `ImWsBridgeHandler`），token 不出服务端。

## 2. ticket 接口契约

| 项 | 值 |
|---|---|
| 方法与路径 | `POST /api/realtime/ticket` |
| 认证 | 必须已登录（`JSESSIONID`）；POST 需 `X-XSRF-TOKEN`（前端 `lib/http` 已自动带） |
| 请求体 | `{}` |
| 响应 | `{code:0, data:{ticket, expires_in:30, ws_path:"/api/im/ws", sse_path:"/api/stats/live"}}` |
| 有效期 | 30 秒（常量 `WsTicketService.TTL`） |
| 存储 | Java 进程内存；重启即全部失效（在途连接会重连并重新换票） |
| 失败 | 未登录 → 401 / 20012；票根无效/重放/过期 → 握手阶段 401 |

**为什么不是"Java 拿内部身份去 Node 换票"**：Node 侧（S1 交付）只提供 `/internal/timers/*`
与内部签名，没有换票接口；S4 的禁止区是 `backend/**`，因此票根在 Java 侧签发与消费。
信任模型等价：Node 仍然只认 Bearer + 内部签名，浏览器仍然只拿一次性随机值。
若以后要改成"Node 签发票根"，只需替换 `WsTicketService` 的两个方法，接口契约不变。

## 3. 现场验证（三条，都能当场做）

1. **票根一次性**

   ```bash
   # 先登录拿 Cookie，再换票
   curl -s -X POST http://localhost:8080/api/realtime/ticket -b cookies.txt \
        -H "X-XSRF-TOKEN: $XSRF" -H "Content-Type: application/json" -d '{}'
   # 拿返回的 ticket 连两次：第一次 101/200，第二次 401
   curl -i "http://localhost:8080/api/stats/live?ticket=<ticket>"
   curl -i "http://localhost:8080/api/stats/live?ticket=<ticket>"
   ```

2. **过期失效**：换票后等 31 秒再连 → 401。
3. **浏览器无 token**：F12 → Network，WS/SSE 的 URL 里只有 `ticket=`；
   Response 里搜 `token`、`Authorization` 均无命中。

> 兼容路径：不带 `ticket` 参数时仍按 `JSESSIONID` 放行（只给 wscat / curl 排障用）。
> 前端两条客户端（`lib/imWs.ts`、`lib/statsSse.ts`）**默认永远换票**，演示时请按上面三条验。

## 4. 定时任务清单与 cron（Java 侧实测频率）

| 任务 | 建议频率 | 本仓库配置（`application.yml`） | Node 入口 |
|---|---|---|---|
| `expire-orders` | 每 10 秒 | `*/10 * * * * ?` | `POST /internal/timers/expire-orders` |
| `refresh-stock` | 每 5 分钟 | `0 */5 * * * ?` | `POST /internal/timers/refresh-stock` |
| `seckill-toggle` | 每 1 分钟 | `0 * * * * ?` | `POST /internal/timers/seckill-toggle` |
| `dashboard-preagg` | 每 5 分钟 | `0 */5 * * * ?` | `POST /internal/timers/dashboard-preagg` |

- 调度器：Quartz（`TimerQuartzConfig`），每任务独立 `JobKey` + `@DisallowConcurrentExecution` +
  `misfire=DoNothing`；**一个任务失败不会影响另外三个**（`TimerJob` 吃掉异常，只记日志与台账）。
- 日志字段固定为：`task / 耗时(ms) / 结果`；同一份事实另有台账接口
  `GET /api/internal/timers`（任务名、开始时间、耗时、是否成功、结果摘要）。
- 手动跑一次：`POST /api/internal/timers/{task}`（演示不必等 cron）。
- 发布注意：`app.internal.secret` 必须等于 Node 的 `INTERNAL_API_SECRET`（≥32 字符），
  本机私网出口 IP 必须登记进 Node 的 `INTERNAL_ALLOWED_IPS`，否则 Node 直接空 404。

## 5. 与下一阶段的边界（J4）

- C 端 App **不使用 ticket**：App 有真实登录态，直连 Node 并自带 `Authorization`，
  ticket 只是"浏览器只有 Cookie"这一约束的补丁。S5 不需要实现换票。
- 大屏的四个数字只走 `GET /api/agency/dashboard-metrics`（Redis `dashboard:preagg`）；
  实时域指标走 `/api/stats/live`（SSE）。两套数据源不要混用，否则"停预聚合数字停更"这条判据会失真。
