## 二、两个关键取舍（第 6 棒和答辩前必读）

### 1. 大屏为什么不是原生 `EventSource`

`/v1/stats/live` 走 `authenticateJwt`，而 passport 只从 **`Authorization: Bearer` 头**取令牌
（`passport.ts` 用 `ExtractJwt.fromAuthHeaderAsBearerToken()`，不认 query token）。
原生 `EventSource` **无法自定义请求头**。要让它跑起来只有两条路：

- 改后端支持 query token —— 但 `statsRouter.ts` 是第 2 棒名下文件，接力规则 §5 不许我动；
- **fetch 流式读取**（本棒选的）：`lib/sse.ts` 手写解析 `event:`/`data:`/`id:`/`retry:` 行，
  协议语义与 EventSource 完全一致（含 `retry` 握手与自动重连），还能拿到 401/403 的明确状态码。

若第 6 棒想换回原生 EventSource：后端加一行 query token 兼容（`statsRouter` 需组员1授权），
前端把 `openLiveStats` 换成 `new EventSource('/v1/stats/live?token=…')` 即可，页面层零改动。

### 2. 客服台「在线点」曾是活跃推断（**已于 2026-11-22 改成真实在线**）

当时的做法：90s 内收到过该会话 msg/notify 实时帧 → 绿点。

补漏后：新增 `GET /v1/im/presence?user_ids=1,2`（批量）与 `/v1/im/presence/:userId`，
读 Redis `im:online:{userId}` 的真实连接状态，前端 30s 刷新一次。
口径仍要分清：**Redis 在线 = 客户端连着**，不等于“在接单”（那要看 `im_agent_status.status`）。
细节见 `docs/plan/补漏-客服接待域.md` §三。

## 三、架构对接说明（第 6 棒联调用）

### 1. 一条 WS 连接服务全部会话（与 C 端单会话的差异）

`ConsultChatScreen` 是单会话页面；`LiveDesk` 是多会话工作台：

- **msg 帧**：`convId === 当前会话` → 立即上屏 + `sendAck`（推进服务端已读游标，第 3 棒 GREATEST 游标）；
  `convId !== 当前会话` → **只累加未读、不 ack**（ack 即已读，乱 ack 会把没看的会话标成已读）；
- **重连对账**：`onStatusChange('connected')` 时只对**当前打开的会话**发 `sync`（目标随切换走）；
  其它会话下次点开时 `GET /im/conversations/:id/messages?since_id=0` 全量兜底（imStore 幂等合并）；
- **发送**：与 C 端完全同款三板斧 —— `imStore.addSendingMessage`（<100ms 上屏）→ WS `msg` 帧 →
  `ack_ok` 改 sent → 3s 超时 failed 可重发（**同 clientMsgId**，服务端 `UNIQUE(conv_id,client_msg_id)` 幂等）。

### 2. B 端鉴权（`src/lib/auth.ts`）

shared-auth 用 **`persist:'full'`** 档（与 C 端 token 只在内存不同）：完整令牌+用户+权限落
localStorage，key 为 `agency_tokens / agency_me / agency_perms`，与 prototype 的 `web_*`、
C 端的 `travel-agent.*` 完全隔离。客服台/大屏是「开着等咨询」的工作面，**刷新页面不掉线**。
baseUrl 为同源 `/v1`（vite 代理 → 3001，`ws:true` 同时代理 WebSocket）。

## 四、踩过的坑（下一棒直接避开）

1. **`request<any[]>` 的 TS 坑**：`Array.isArray` 收窄后 else 分支变 `never`，
   `history?.list` 直接报 TS2339。历史接口一律 `request<any>` 再手工归一（本棒已修）。
2. **WS 回调里的过期闭包**：`activeConvId` 若被 `onMessage` 闭包捕获会一直是旧值。
   本棒用 `activeConvRef`（ref）+ state 双轨：渲染用 state，帧路由用 ref。
3. **EventSource 的 401 是黑盒**：原生 EventSource 对鉴权失败只给 `onerror`，永远不知道是 401 还是断网 —— 这也是放弃它的第二个理由。fetch 方案里 401/403 有明确状态码，重连节奏好控制。
4. **SSE 流里的 `\r\n`**：有些代理会把 `\n\n` 分隔符变成 `\r\n\r\n`，先统一替换再按空行切块，否则事件永远解析不出来。
5. **`degraded` 红闪要"闪完就停"**：CSS `animation: ... 3` 跑 3 个脉冲后自动停，不要写 `infinite` —— 持续红闪会让演示画面像出了事故。
6. **补间要容忍迟到帧**：SSE 5s 一拍，缓动 1s；用 rAF 从当前显示值滑向新值（不是从 0），数字不会"归零再跳"。
7. **大屏页面卸载必须 `handle.close()`**：否则 fetch 流、AbortController、重连定时器全泄漏，React StrictMode 双挂载下尤其明显（本棒已在 useEffect cleanup 里处理）。
