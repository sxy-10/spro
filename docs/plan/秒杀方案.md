# 秒杀方案（阶段二 · 组员3）

## 一、核心决策：秒杀名额独立（方案 A）

普通下单走 `total_seats / locked_seats / sold_seats`，秒杀走 `seckill_total_seats / seckill_sold_seats`，两套名额互不扣减。

**为什么不共用 `total_seats`**：普通下单是条件 UPDATE 锁 `locked_seats`，秒杀如果也写同一张表同一组列，高并发下两边会互相覆盖、超卖。独立名额是最省事的隔离方案。

## 二、链路

```
POST /v1/seckill/:routeId
  │
  ├─ 1. 校验登录 + 参数
  ├─ 2. 查 route_stock 拿到 travel_date（秒杀日期）
  ├─ 3. Lua 预扣 Redis：stock:{routeId}:{date}
  │     ├─ 成功 → 继续
  │     ├─ sold_out → 直接返回 {status:'sold_out'}，不写库
  │     └─ redis_unavailable → 返回 503（不兜底走数据库，否则失去挡流量意义）
  │
  ├─ 4. XADD seckill:stream 写入消息 {reqId, userId, routeId, date, people}
  │     └─ 发失败 → 回补 Redis 库存（INCRBY 回去），返回失败
  │
  └─ 5. 立刻返回 {status:'queued', reqId}   ← 用户感知毫秒级

GET /v1/seckill/result/:reqId
  └─ 查 Redis key:result:{reqId} → {status:'pending'|'success'|'failed', order_id?}

消费者（后台常驻）：
  XREADGROUP GROUP seckill-group
    → 按 req_id 查 tour_order 查重（幂等）
    → BEGIN
    → SELECT ... FROM route_stock WHERE route_id=? AND travel_date=? FOR UPDATE
    → 乐观锁 UPDATE：SET seckill_sold_seats+1, version+1 WHERE version=?
    → INSERT tour_order (req_id, ...)
    → COMMIT
    → 写 Redis result:success + XACK
  失败 → 重试 3 次仍失败 → XADD seckill:stream:dlq + result:failed
```

## 三、Key 清单

| Key | 类型 | 写入方 | TTL |
|---|---|---|---|
| `stock:{routeId}:{date}` | String(数字) | stockCache 预热 | 活动结束时间 |
| `seckill:stream` | Stream | producer XADD | 无 |
| `seckill:stream:dlq` | Stream | consumer 死信 | 无 |
| `seckill:result:{reqId}` | String(JSON) | consumer | 600s |

## 四、Redis 挂了怎么办

直接拒绝下单（返回 `redis_unavailable`），不降级走数据库。理由：秒杀的意义就是用 Redis 挡流量，一旦 Redis 挂了还打数据库，和没做秒杀一样。

## 五、验收标准

1. `stock:1:2026-12-01` = 10，100 并发打 POST /seckill/1，只有 10 个返回 queued，其余 sold_out
2. `SELECT COUNT(*) FROM tour_order WHERE req_id IS NOT NULL` = 10
3. 关掉消费者，再压 5 轮，`XLEN seckill:stream` 涨；重启消费者后自动补单
4. 同一条消息重投，订单数不变（req_id 唯一约束挡掉）
5. `seckill_sold_seats` 恒 ≤ `seckill_total_seats`
