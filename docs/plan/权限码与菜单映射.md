# 权限码与菜单映射（S2 交接件 · 2026-11-25）

给 S3（平台方 + 日志页）复用：菜单怎么出现、按钮怎么灰、什么权限码对应哪个页面，全在这里。**不允许再按角色字符串判断**（`role === 'ADMIN'` 一出现就算违规）。

## 1. 数据来源与生命周期

| 步骤 | 谁做 | 说明 |
|---|---|---|
| 下发 | Node `GET /v1/users/me/permissions` | 返回 `{menus:[...], buttons:[...]}`，menus 是树（`permission_id/parent_id/name/code/path/icon/sort/children`），buttons 是扁平数组（`permission_id/name/code/resource_type`） |
| 缓存 | Java 登录时写进 Session | 键 `node.permissions`；`/api/me` 原样下发，页面刷新不再打 Node |
| 失效 | 重新登录 | 改角色后**必须重新登录**才生效（与 Node 的权限缓存一致） |
| 判定 | 前端 | 有 `SUPER_ADMIN` 角色 → 全通过；否则按 `buttons[].code` 精确匹配 |

> 一句话：**菜单出现与否看权限码，能不能点是权限码，删不删得掉还是权限码**。角色只用来做"全通过"这一个例外。

## 2. B 端（`/agency/**`）映射

前端实现见 `java-web/agency-web/src/components/AppLayout.tsx`（菜单）与 `components/Permission.tsx`（按钮）。

| 页面 | 路由 | 菜单显示所需权限码 | 页面聚合接口 | 关键按钮 → 权限码 |
|---|---|---|---|---|
| 工作台 | `/agency/dashboard` | `order:manage:query` | `GET /api/agency/dashboard` | — |
| 线路列表 | `/agency/routes` | `route:line:query` | `GET /api/agency/routes` | 新建 → `route:line:add`；编辑 → `route:line:update` |
| 线路表单 | `/agency/routes/new`、`/agency/routes/:id/edit` | 同列表 | 同列表（编辑按 id 回填） | 提交 → `route:line:add` / `route:line:update` |
| 订单列表 | `/agency/orders` | `order:manage:query` | `GET /api/agency/orders`、`GET /api/agency/orders/{id}` | 确认 → `order:manage:update` |
| 库存 | `/agency/stock` | `route:line:query` | `GET /api/agency/stock/{routeId}` | 改名额 → `route:line:update` |
| 客户 | `/agency/customers` | `customer:customer:query` | `GET /api/agency/customers`、`GET /api/agency/customers/{id}` | 保存备注 → `customer:customer:update` |

`staff02`（AGENCY_STAFF）预期效果：能看到工作台/线路/订单（只读），**看不到"新建线路"与"确认订单"**，因为缺 `route:line:add` 与 `order:manage:update`。

## 3. 平台方（`/platform/**`，S3 填）

S3 只需把同一套机制复制过去，**不要另写一份权限逻辑**：

| 页面 | 路由 | 菜单显示所需权限码 | 聚合接口 |
|---|---|---|---|
| 平台概览 | `/platform/dashboard` | `order:manage:query` | `GET /api/platform/overview` |
| 机构管理 | `/platform/agencies` | `system:agency:query` | `GET /api/platform/agencies` |
| 用户与角色 | `/platform/users`、`/platform/roles` | `system:user:query`、`system:role:query` | `GET /api/platform/users`、`GET /api/platform/roles` |
| 平台订单 | `/platform/orders` | `order:manage:query` | `GET /api/platform/orders` |
| 财务 | `/platform/finance` | `finance:platform:query` | `GET /api/platform/finance/summary` 等 |
| AI 服务 | `/platform/ai-service` | `ai:service:query` | `GET /api/platform/ai-service` |
| 日志三页 | `/platform/logs/{system,operation,login}` | `system:permission:query` | `GET /api/platform/logs?type=...` |

## 4. 接缝约定（S2 → S3）

1. **可复用**：`lib/http.ts`（含 `qs()`）、`lib/auth.tsx` 的 `can(code)`、`components/Permission.tsx`、`components/AppLayout.tsx` 的菜单渲染方式。
2. **不要改**：`AppLayout` 里的 `AGENCY_MENU` 常量归 S2；S3 在同一个文件里**追加** `PLATFORM_MENU` 并按角色/权限选择菜单组，避免两份 Layout 分叉。
3. **接口**：S3 的 `/api/platform/*` 直接注入 `NodeApiClient`（已在容器里，签名/包络/重试都做好了），**不要重写签名**。
4. **字段风格**：一律透传 Node 的 snake_case，不在 Java 层做驼峰转换，也不在前端做映射。
