## 二、表结构变更

### `im_conversation` 新增列（只加不改，存量数据天然兼容）

| 列 | 类型 | 含义 |
|---|---|---|
| `assignee_id` | BIGINT UNSIGNED NULL | 当前接待客服；**NULL = 无人接待** |
| `status` | ENUM('ACTIVE','CLOSED') | 会话生命周期，默认 ACTIVE |
| `queued_at` | DATETIME(3) NULL | 最近一次进入待接入队列的时间（算等待时长） |
| `assigned_at` | DATETIME(3) NULL | 最近一次被接入的时间 |
| `closed_at` | DATETIME(3) NULL | 结单时间 |
| `agent_note` | VARCHAR(255) NULL | 结单备注 |

索引：`idx_im_conv_pool(status, assignee_id, last_message_at)`、`idx_im_conv_assignee(assignee_id, status, last_message_at)`；
外键：`fk_im_conv_assignee → sys_user(id) ON DELETE SET NULL`。

### 新增表

- `im_agent_status(user_id PK, status ENUM('ONLINE','AWAY','OFFLINE'), max_concurrent TINYINT, last_heartbeat_at)`
- `im_quick_reply(id, owner_id NULL=公共, category, content, sort, enabled, seed_key UNIQUE)`
- `im_rating(id, conversation_id, rater_id, agent_id, score 1..5, comment, tags JSON, UNIQUE(conversation_id, rater_id))`

### 全项目唯一「待接入」口径

```sql
status = 'ACTIVE' AND assignee_id IS NULL
```

SQL、接口、前端、文档四处都用这一条。**不要**再引入 `WAITING` 之类的第二套状态，
否则「池子里到底有什么」会出现两种答案。

## 三、接口清单

全部挂在 `/v1` 下，统一 `authenticateJwt` + `requireAction`（权限码见括号）。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/im/agent/queue?scope=pool\|mine\|closed\|all` | `im:agent:query` | 队列行含：客户名/脱敏手机/最后一条预览/未读数/`wait_seconds`/`sla_breached`/`counters` |
| POST | `/im/agent/conversations/:id/claim` | `im:agent:manage` | 接入。行锁 `FOR UPDATE` 防抢单；超并发上限拒绝；重复接入返回 `claimed:false` |
| POST | `/im/agent/conversations/:id/release` | `im:agent:manage` | 放回待接入池 |
| POST | `/im/agent/conversations/:id/transfer` | `im:agent:manage` | 转交；目标必须 `ONLINE` 且未满负荷 |
| POST | `/im/agent/conversations/:id/close` | `im:agent:manage` | 结单，可带 `note` |
| POST | `/im/agent/conversations/:id/reopen` | `im:agent:manage` | 重开（客户又回来了） |
| POST | `/im/agent/auto-assign` | `im:agent:manage` | 一键分配：FIFO + 最小负载贪心，单事务 |
| GET | `/im/agent/status` | `im:agent:query` | 我的状态 + 负载 + WS 是否在线 |
| PUT | `/im/agent/status` | `im:agent:manage` | 切接待状态 / 改并发上限 |
| GET | `/im/agent/candidates` | `im:agent:query` | 可转交的客服（在线且未满） |
| GET | `/im/presence?user_ids=1,2` | `im:agent:query` | 批量在线（Redis 真实连接，不是推断） |
| GET | `/im/presence/:userId` | `im:agent:query` | 单人在线 |
| GET | `/im/quick-replies` | `im:quick_reply:query` | 公共 + 我的，个人优先 |
| POST | `/im/quick-replies` | `im:quick_reply:manage` | 新增个人话术 |
| DELETE | `/im/quick-replies/:id` | `im:quick_reply:manage` | 只能删自己的；公共话术 403 |
| POST | `/im/conversations/:id/rating` | `im:rating:add` | 客户评价（参与者、一会话一次） |
| GET | `/im/agent/ratings?agent_id=` | `im:rating:query` | 评分汇总（均分 + 分布 + 最近 10 条） |

**在线状态的两层口径**（答辩必答）：

- `Redis im:online:{userId}` = **连接是否活着**（TTL 60s，进程被 kill 会自然消失）；
- `im_agent_status.status` = **人为选择的接待意愿**。

`online=true` 不代表“在接单”，要 `online && status='ONLINE' && load < max_concurrent` 才是“能派单”。

## 四、前端改动

### `frontend/agency-web/src/pages/LiveDesk.tsx`（重写）

- 左栏三段式：**待接入 / 我的接待 / 已结束**，角标来自 `counters`（一次请求带回，不额外打接口）；
- 会话项：客户名 + 脱敏手机 + 最后一条消息预览 + 已等待时长（超 SLA 红底红字）+ 未读红点；
- 底部固定「我的负载 x/y」+ 接待状态三按钮（落库）+「一键分配给在线客服」；
- 中栏：待接入时显示“只能看预览”，一键接入后自动补拉历史；已接入才允许发消息；
- 右栏：客户信息、真实在线状态、转交下拉、结单备注输入、满意度评分卡（均分 + 五档分布 + 最近两条）；
- 快捷话术接口化：公共话术只读，个人话术可删，底部可新增。

### `frontend/src/components/ConsultChatScreen.tsx`（加一个按钮）

头部加「＋ 发起咨询」：`POST /im/conversations {}` 建一条新会话并切过去。
不传 `member_ids` → 只有游客自己一个 participant → 自动落到客服台「待接入」队列（抢单模式）。

### 实时性口径（重要，别吹过头）

- **已接入会话**：走第 4 棒 WS（`msg`/`notify` 按 participant 投递），毫秒级；
- **待接入池**：客服还不是 participant，服务端不会给他推帧 → 前端 **15s 兜底刷新**（一次轻查询），
  接入后立刻转为 WS 实时。

宁可写 15 秒，也不假装池子是实时的。

## 六、踩过的坑（直接避开）

1. **动态 SQL 的双层引号**
   `SET @ddl = 'ALTER TABLE ... COMMENT ''中文'''` —— 结尾要 **三个**单引号（`''` 转义 + `'` 收尾），
   写成两个就会把后面的 `,` 吞进字符串里，报语法错误。
   **结论：动态语句里不写 `COMMENT`**，注释放 SQL 文件的文字说明里。

2. **`INSERT ... SELECT ... WHERE NOT EXISTS (SELECT ... FROM 同表)` 有 1093 风险**
   种子话术改成给 `im_quick_reply` 加 `seed_key` 唯一键 + `INSERT IGNORE ... VALUES`，绝对幂等。

3. **`12_im_perm.sql` 的 `AGENT` 是空壳角色**
   它 `INSERT IGNORE` 建了个 code=AGENT 的「业务专员」，但库里早就有 `AGENCY_STAFF`（名字一样），
   seed 出来的 staff02 绑的是后者。结果：给 AGENT 授权，真人一个都用不了。
   **验收要验到「用户有效权限」，不能只看角色。**

4. **Casbin 策略缓存 30s**
   改完 `sys_role_permission` 立刻调接口可能还是 403。要么等 30s，要么重启进程
   （`invalidatePolicyCache()` 只在授权写接口里被调用，直接跑 SQL 不会触发）。

5. **`page()` 是 `.strict()`**
   `GET /im/agent/queue` 的 query 里多传一个字段就 400。新增查询参数必须同时加进 `page(..., filters)`。

6. **不再用 `list()` 拼多表分页**
   `list()` 的 select 和 count 共用一组参数，而队列的 select 里有 4 个相关子查询占位符，
   参数一混就错位。改成手写两条查询（分页/排序仍走 `page()` 白名单，SQL 注入面不变）。

## 七、还没做的（明确边界）

- **C 端评价入口**：接口已通，页面只有客服侧看评分；C 端评分 UI 留给后续（第 4 棒页面归属）。
- **多客服同时在线时的会话广播**：池子仍是 15s 刷新，没做服务端向所有客服推「新会话」事件
  （要动 `wsServer` 的投递范围，属于第 4 棒文件）。
- **会话归档/数据保留策略**：`CLOSED` 会话永久留在表里，没有冷热分层。
- **转交时的系统消息**：转交只改归属，不在会话里插 `SYSTEM` 消息（避免打乱第 3 棒的发号顺序）。
