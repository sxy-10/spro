### 2.2 口径（重新拉取代码后修正的关键点）

**坑 1：`08_rbac_complete.sql` 会让游客拿到「后台菜单」。**
脚本给 TOURIST 授了 6 个 C 端按钮：`chat:session:query`、`chat:message:query`、`chat:message:add`、
`itinerary:plan:add`、`order:booking:add`、`order:booking:query`。
后端 `rbacRouter.ts:visiblePermissionIds()` 会沿 `parent_id` 补祖先，所以游客的 `menus` 里
**也会出现** `/chat`、`/orders`、`/orders/booking`、`/itineraries`、`/itineraries/plans`。
→ 绝不能用「菜单 path 是不是 `/admin` `/orders` `/itineraries`」判断管理中台入口，
否则游客会被误判成管理员（拉取前那版就是这么错的，已修并有回归用例）。
现在 `hasConsoleAccess()` 只看**管理类按钮码**（`system:*` / `route:line:*` / `order:manage:*` /
`itinerary:plan:query|update|delete|export`）与 `system` 模块菜单（`/admin*`），与 `usePermission` 同源。

**坑 2：后端 `menus` 是后台菜单树，不是 C 端 Tab。**
只有显式的前台 Tab 菜单（如 `app:plan` / `/app/explore`）才进入「严格按菜单渲染」分支；
08 脚本没有这类菜单，所以当前按权限视角决定 Tab 集合：
游客（未登录或仅 C 端权限）→ 2 个 Tab（`plan` + `profile`）；超管/社管（有管理类权限）→ 全部 5 个 Tab。

**坑 3：Tab 可见性 ≠ 页面可达性。**
游客点「创建计划」会跳到智能体页、看行程会跳到行程页。若外壳只放行可见 Tab，
游客会被守卫弹回首页，核心闭环走不通。因此 `deriveAllowedScreens()` =
可见 Tab + 下钻页（`agent` / `itinerary` / `explore`）+ 有条件加入的 `admin`。
底部导航仍然是 2 个 Tab，越权进 admin 依旧被挡。

**坑 4：Idempotency-Key 必须每次换。**
后端按 key 缓存首次结果，复用同一个 key 会被当成同一次提交。`RoleManage` 在**点击保存的瞬间**
调 `newIdempotencyKey()`，随 `RolePermissionDraft` 交给父组件，不存 state、不复用。
`lib/http.ts` 的写请求拦截器也自动生成 key，但显式传入时以传入值为准。

## 三、怎么用（下一阶段接线）

`RoleManage` / `PermissionTree` 全部由 props 驱动，接接口时组件不用改：

```tsx
const [roles, setRoles] = useState<RoleItem[]>([]);
const [tree, setTree] = useState<PermissionTreeNode[]>([]);
const [assigned, setAssigned] = useState<string[]>([]);

useEffect(() => {
  void request<{ list: RoleItem[] }>('/roles').then((d) => setRoles(d.list));
  void request<{ menus: PermissionTreeNode[] }>('/permissions').then((d) => setTree(d.menus));
}, []);

const selectRole = (roleId: string) =>
  void request<{ permission_ids: string[] }>(`/roles/${roleId}/permissions`)
    .then((d) => setAssigned(d.permission_ids));

const save = async ({ roleId, permissionIds, idempotencyKey }: RolePermissionDraft) => {
  await request(`/roles/${roleId}/permissions`, 'PUT', { permission_ids: permissionIds },
    { idempotencyKey });        // 每次保存都是新 key
  await refreshPermissions();  // 改完立刻同步当前账号 menus/buttons
};

<RoleManage roles={roles} permissionTree={tree} selectedRoleId={currentRoleId}
            assignedIds={assigned} onSelectRole={selectRole} onSave={save} />
```

**界面接线位置**：`App.tsx` 的 `admin` 分支可加一个「角色权限配置」子屏（或直接复用 `RoleManage`），
用 `hasConsoleAccess(session.permissions)` 守门。本轮**没有挂路由**，避免提前引入业务数据流。

**权限刷新**：`App.tsx` 已订阅 `useSession()`，`refreshPermissions()` 写回会话后 Tab 与按钮自动重渲染。
`AdminScreen` 的「+ 上架新路线」由 `<AuthPermission code="route:line:add">` 控制，
取消 AGENCY_ADMIN 的该权限后刷新即消失（验收点）。
