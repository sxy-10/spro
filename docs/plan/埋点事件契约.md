# 实时推荐埋点契约（T5 Node 入水口）

## 接口

`POST /v1/events` 可匿名调用，也可带 Bearer 登录态。请求可以是单条 JSON 对象或 1–50 条对象数组；若带登录态，每条事件的 `userId` 必须等于当前认证用户。响应 `202` 表示已接收，不代表 Kafka 已持久化；发送失败只写本地结构化日志，不阻塞前端主链路。

```json
{
  "userId": "123",
  "itemType": "PRODUCT",
  "itemId": "45",
  "eventType": "click",
  "ts": "2026-11-25T06:00:00.000Z",
  "sessionId": "client-session-id",
  "extra": { "source": "home" }
}
```

`eventType` 仅允许 `impression | click | dwell | like | favorite | share | order`。`ts` 必须是带时区的 ISO-8601 时间；`itemType` 最长 40 字符、`itemId` 最长 64 字符、`sessionId` 最长 128 字符。`extra` 为可选对象，只放非敏感、事件专属属性，禁止密码、token、手机号和签名。

## Kafka

- Topic：`rec.events`；message key 为字符串 `userId`，同一用户固定落同一分区并有序。
- value 为上述事件 JSON；入站批次按单次 Kafka `send` 写出。
- 本接口不写业务数据库，不等待 Flink；broker 暂时不可用时会返回 `202`，失败记录在 Node JSON 日志中。
- 下游画像 key 及格式由负责 Flink 的阶段冻结；此接口不自行改写画像。
