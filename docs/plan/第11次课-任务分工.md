## 2. 全组先定死的技术方案（不定死，六个人会写出六套）

| 决策点 | 结论 | 对得上笔记哪一句 |
|---|---|---|
| 通信框架 | 原生 `ws`，不用 Socket.IO、不用云 IM | §十一：Socket.IO 把重连/心跳/ACK 都内置了，"四个核心问题"讲不出来；云服务"把技术栈全屏蔽了" |
| 端口 | 复用 3001，`/v1/im/ws` 同端口升级 | 不新增端口，Nginx 只多一段 Upgrade |
| 握手鉴权 | `ws://host/v1/im/ws?token=<access token>`，复用 passport JWT + `api_session` | 前端 token 只在内存，与现有一致 |
| 心跳 | 客户端 30s `ping`，服务端 `pong`；**10s 收不到 pong 断开**（`HEARTBEAT_MS=30000` / `PONG_TIMEOUT_MS=10000`） | §十 |
| 重连 | 1/2/4/8… 封顶 30s，±20% 抖动 | §十：防重连风暴 |
| 顺序 | `INCR im:seq:{convId}` 发号，落库 `UNIQUE(conv_id, seq)` | §十三：时间戳靠不住，发号只能一处 |
| 幂等 | `UNIQUE(conv_id, client_msg_id)`，重复发送回原 seq | §十二："一条消息发两次是可能的" |
| 离线 | `last_seq` 游标 + `?since=` 增量，每批 500 | §十四 |
| 降级 | WS 不通 → 长轮询 `/v1/im/poll`；Redis 不通 → `SELECT MAX(seq)+1 FOR UPDATE` | §八"轮询垫底 WS 当家" |
| 消息存储 | 新建 `im_*` 表，**不动** `chat_*`（AI 对话域已上线） | 避免污染 token 统计与回溯 |
| 大屏 | SSE 单向推送 | §八：SSE 就是服务端单向推，正好是大屏 |

**WS 协议帧（`t` 区分，`v:1`）**

```
C→S  auth {token}   ping {ts}   msg {convId,clientMsgId,type,content}
     ack {convId,seq}           sync {convId,lastSeq}
S→C  auth_ok {userId,deviceId}  pong {ts,serverTs}
     msg {convId,seq,clientMsgId,senderId,type,content,ts}
     ack_ok {clientMsgId,seq}   notify {kind,convId,preview}   error {code,msg}
```

**新增接口（补进 `API_V1.md` §IM，写接口一律带 `Idempotency-Key`）**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/im/conversations` | 我的会话 + 未读数 |
| POST | `/v1/im/conversations` | 游客发起咨询 |
| GET | `/v1/im/conversations/:id/messages?since=&limit=50` | 增量拉取（离线补偿/降级共用） |
| POST | `/v1/im/messages` | HTTP 降级发送，与 WS `msg` 同一 service |
| POST | `/v1/im/conversations/:id/read` | 已读游标 |
| GET | `/v1/im/poll?convId=&since=` | 长轮询兜底，最长 25s |
| GET | `/v1/stats/live` | SSE 大屏数据流 |

### 接力规则（五条，不许破）

1. **每棒结束当天 18:00 前**写 `docs/plan/交接-阶段N.md`：做了什么 / 怎么跑 / 坑在哪 / 下一棒要用哪些文件与接口。
2. 下一棒开工第一件事：**跑上一棒的验收命令**，跑不通当场退回，**不往后传**。
3. 一棒只动自己名下的文件（见 §5）；要改上一棒交付的接口签名，**先跟上一棒确认并同步改 `API_V1.md`**。
4. 工作量按"半天"粒度留缓冲，没做完的写进交接文档"未完成项"，交给下一棒。
5. 不许"顺手"帮别人写代码 —— 想帮就写进交接文档的建议里，由接棒人执行。

**串行的代价（必须知道）**

| 问题 | 说明 | 缓解 |
|---|---|---|
| 没有并行收益 | 任何时刻只有 1 人在写代码，总工期不会比并行短 | 清晰优先，可接受 |
| 风险压在第 6 棒 | 联调、录屏、答辩材料全在最后 1.5 天 | 每棒自带验收命令，坏了**当场退回**，不积压到最后 |
| 交接断层 | 下一棒看不懂上一棒代码就卡住 | 交接文档必写"怎么跑 + 坑在哪"，交棒当天口头过一遍接口 |
| 时间不够只能砍功能 | 砍时间就是砍质量 | 砍序：大屏折线图 → 群聊文档 → 图片三档留两档 → 长轮询降级 |

**不能砍**：发号唯一、幂等唯一索引、离线补齐、心跳退避 —— 这四条砍了就讲不圆。
